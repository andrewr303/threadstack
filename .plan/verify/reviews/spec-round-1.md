## Findings

### S1 — Major: pairing alphabet differs across the transport

REQ-7 pairing could fail for a valid server response. At first review,
`packages/plugins/plugin-browser-sessions/src/service.ts`, `startPair`, generated eight-character
codes with `randomBytes(6).toString('base64url').toUpperCase()`, including `_` and `-`. The extension's
`bridge.ts`, `pair`, accepts only `[A-Za-z0-9]{8}`. Roughly one in five generated codes could therefore
be rejected as invalid pairing details. The initial service test checked length only.

Repair required: a single agreed alphabet with a cross-boundary test, including all generated byte
values. The author reports this repaired; the bounded recheck must inspect and run that test.

### S2 — Major: an in-flight provider navigation can change the submission target

REQ-11 requires delivery to the exact session/account. `extension/src/core/embed/session-delivery.ts`,
`deliverProviderMessage`, validated a string snapshot of the URL before an asynchronous wait for
the Send button. It then clicked the newly queried button without revalidating the live URL.

`delivery-navigation-probe.mts` demonstrates the failure using JSDOM: the requested Claude URL is
`/chat/one`; while Send is disabled, history changes to `/chat/two`; enabling Send leads to
`delivered: true` at `/chat/two`. The probe assertion fails with exit 1. This is a synthetic safety
failure, not proof about a real provider's rendering behavior.

Repair required: retain a live URL/document identity source and check it immediately before draft
mutation and submission, including after awaits. Refuse/cancel a changed destination and add the
regression through the actual content handler. The lead assigned the repair; recheck pending.

### S3 — Major: existing automatic task links and unlink suppression were absent

REQ-9 AC-3 requires importing existing Paperclip-task/coding-session cross-links as `origin: auto`
and keeping a founder's unlink from being recreated. At first review, the inventory path only
called `linkStartedSession` for sessions started by agent actions; no path created an `auto` link
from the library, and there was no automatic-link tombstone. The guard/type references to `auto`
did not implement its creation.

Repair required: an explicit bounded projection of existing links, company/task/session validation,
and persistent unlink suppression. The author reports the server implementation and tests repaired,
with extension projection being integrated. Bounded recheck pending.

### S4 — Major: observation and settled-change semantics were not implemented

REQ-10 AC-1/2/8 require five seconds of settled state and truthful observation freshness. At first
review, `bridge-query.ts` computed `observed` solely from the existence of `agentState` and
`agentStateAt`; neither field established that a frame remained loaded. A once-observed closed
session could consequently remain observed indefinitely. `bridge.ts`, `syncInventory`, emitted an
event whenever a sampled state differed, without a five-second settlement gate. The existing
background write throttle is not a debounce after the change and does not establish frame presence.

Repair required: actual frame observation ownership/lifecycle and a settled transition ledger,
including transient unknown states and reconnect behavior. The lead assigned this repair; recheck
pending. Merely expiring `agentStateAt` would misclassify a long-running unchanged loaded frame.

### S5 — Major: a run-only change hint performs no fallback refresh

REQ-12 AC-2 explicitly covers run events that name no task. At first review, the plugin queued
`runIds`, but `runPaperclipHintSync` accepted only `issueIds` and fetched nothing for an empty issue
list. A run-only hint could therefore leave its task stale until the periodic timer.

Repair required: resolve the named company's run step to affected tasks, keeping company scope and
cursor ownership intact. The lead reports the repair and a red/green regression plus existing sync
checks. Bounded source/test recheck pending.

### S6 — Medium: state comments lack the required session identity and opening action

REQ-10 AC-3 requires provider/account labels and an `Open session` link. The initial
`state-changes.ts` body contained only the title, state and hidden deduplication marker. That left
comments ambiguous between accounts and gave the user no direct route to the affected session.

Repair required: bounded quoted title, provider/account labels, safe actionable link, and no other
transcript text. The author reports the body and tests repaired; bounded recheck pending.

### S7 — Medium: agent-facing data drops the untrusted marker

REQ-8 AC-14 requires `data.untrusted === true` as well as fenced warning text. Initially,
`normalizeRead` rebuilt list/search/read result objects and `agentData` did not restore the marker,
so these returned data objects lacked it. The fenced content warning was present.

The current direct synthetic probe now returns
`{"messages":[{"text":"fixture"}],"untrusted":true}`. This narrow repair was observed during
the review. The full tool normalization paths still belong in the bounded final recheck.

### S8 — Medium: a non-JSON responder could trigger service startup

REQ-4 AC-6 says a different application answering on the configured port must produce unreachable
and no start request. Initially, `lifecycle.ts` awaited `res.json()` inside `request`; an HTML 200
response threw into the same offline path as a network failure, which could start the helper.

The current synthetic lifecycle probe now produces state `unreachable`, reason `not_paperclip`,
and zero helper start requests for an HTML 200 responder. This narrow repair was independently
observed. The retained probe uses only injected fetch/helper fixtures.

### S9 — Medium: five-second outage replacement has no signal beyond the thirty-second poll

REQ-5 AC-3 requires replacing an active failed frame with the status panel within five seconds.
`lifecycle.ts` schedules healthy polls at 30 seconds, while `PaperclipConnection.tsx` and
`ThreadkeeperHostBridge.tsx` contain no additional server-outage notification or refresh trigger.
An outage immediately after a healthy poll can therefore leave the snapshot running and frame
visible for most of thirty seconds. REQ-4's healthy polling cadence should be preserved by an
event/bridge-failure-driven immediate probe, or this contract conflict must be explicitly resolved;
the five-second claim cannot be inferred from the current timer.
