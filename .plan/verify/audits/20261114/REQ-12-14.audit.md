## 3. Findings (most severe first)

1. **Major — key transport (D-4 assumes loopback).** `client.ts:54-66` accepts any `http:` origin, and `credentials.ts:118-123` and `bridge.ts:131,145` use it unchanged. If the server URL is a LAN or remote `http://` host, the `/bridge/secret` response value and the `saveSecret` POST body travel in cleartext. **Fix:** in `credentials.ts` and `bridge.ts` `resolveSecret`, refuse secret transfer unless the origin is loopback or `https:`. **Test:** backend or bridge with `http://10.0.0.5:3100` must throw before calling fetch.

2. **Major — AC-2/AC-6 storage leak.** `credentials.link` (`credentials.ts:250-264`) never clears the local value. Sequence:
   - A stored Voyage key exists, and the user presses Link.
   - The value stays in IndexedDB and in helper backups. The field hides it and is read-only (`SettingsDialog.tsx:380-383`), so the user can't clear it.
   - If the secret is later deleted, the status refresh drops the link (`credentials.ts:276`) and `credentialPresent` and the feature calls quietly use the stale local value.

   **Fix:** after a successful readback in `credentials.link`, clear the local value in a transaction, the same way `moveModelKeys` does (`credentials.ts`). **Test:** link over a stored value, then assert the IndexedDB row and `writeBackup` output are free of it.

3. **Major — REQ-12 hint failure breaks the bridge.** `bridge.ts:315` awaits `onHint` inside the tick's `try`. `runPaperclipHintSync` throws on any per-issue error: a 404 from a deleted task, `forbidden` at `sync.ts:369,708`, or a network failure. The `catch` at `bridge.ts:316-318` then:
   - marks the company disconnected and drops the rest of the hints (the plugin already removed them at `service.ts:142`);
   - fires `onChange`, which opens the live socket.

   **Fix:** catch per hint in `background.ts` `onHint`, and skip `not_found`/`forbidden` per issue in `sync.ts`. **Test:** a hint naming one missing and one valid issue stores the valid one and the bridge stays connected.

4. **Major — REQ-12 hints stall the bridge.** The hint is awaited behind the periodic sync (`background.ts:526-536`, 50 s budget) or "Sync now" (`background.ts:1804`, 240 s). That holds the company's poll loop past `OFFLINE_MS = 40_000` (`contracts.ts:7`). The plugin's heartbeat deadline then cancels pending agent requests (`service.ts:44`), and `domainEvent` stops queueing hints (`service.ts:288`). **Fix:** queue the hint (fire-and-forget into `serializePaperclipWork`) instead of awaiting it in `tickCompany`. **Test:** a fake hanging `onHint` must not delay the next poll.

5. **Major — AC-1/FR-4 regression when paired but not sharing.** `domainEvent` returns early when `!state.shared` (`service.ts:288`). Meanwhile the extension suppresses the socket whenever the bridge is connected (`background.ts:585`), and that check ignores sharing. On a local server with session sharing off, the result is no hints and no socket, so only the 5-minute timer runs. **Fix:** gate hints on pairing (`tokenHash`), not sharing, in `service.ts`. **Test:** paired-but-unshared still produces a hint.

6. **Major — consent hygiene, FR-1 edge.** `credentials.source` builds the backend for the *new* company and clears *its* links (`credentials.ts:238-243`). The old company keeps `allowSecretTransfer: true` and its links on the server. Clearing the source in the UI is local-only (`PaperclipCredentials.tsx:83`). **Fix:** clear the previous company's config, and also clear on deselect (`credentials.ts`, `PaperclipCredentials.tsx`). **Test:** switching A→B posts a cleared config for A.

7. **Major — AC-5.** `secret()` has no `this.audit(...)` (`service.ts:275-286`). **Fix:** after resolving, log `browser_sessions.secret_read` with `{keyName, extensionVersion, browser}` from the bridge state and no value. **Test:** in `service.spec.ts`, assert `activity.log` was called once and does not contain the value.

8. **Major — functional.** `cloud-client.ts:117` checks the raw `workerBearerToken`. Line 63 correctly uses `credentialPresent`. After a move, cloud enrichment, query embeddings and rerank are all refused as "not configured". **Fix:** use `credentialPresent` at line 117. **Test:** a linked token with an empty local value is allowed.

9. **Minor (likely Major; needs a run to confirm) — throttling.** The server allows 30 secret reads per minute per company and plugin (`server/src/services/plugin-secrets-handler.ts:195`). Every feature call reads again because nothing is cached (`credentials.ts:87`). Bulk indexing can exceed the limit and show the "not running" pause. **Fix:** either cache in memory per feature batch for a short time (≤60 s, which still meets the rotation requirement) or raise the limit. **Test:** 40 embed calls in one minute.

10. **Minor — FR-2 negative.** A caller without the token gets `not_paired`/401 (`service.ts:48`, `worker.ts:53`). The contract says `denied`.

11. **Minor — AC-4 notice.** The catch-all at `credentials.ts:92,100` reports consent-off, a deleted secret and throttling as "Paperclip is not running". A deleted secret should count as absent (FR-1 negative).

12. **Minor — UI and test accuracy.**
    - `SettingsDialog.tsx:277,289,321,603` use the raw `awsCredentialsReady`, so linked AWS keys show "Needs keys".
    - Secret status differs between the two UIs: `credentials.ts:136` treats anything not `deleted` as present, while the Paperclip UI requires `active`.
    - The hints test name claims cursors are unchanged but never inspects the store.
    - The AC-4 test does not assert zero requests.

**Risks I checked and found handled:**
- **Hints don't advance the cursor:** they never touch the cursor or run marks, so a hint can't cause a missed periodic update. A leftover run mark only causes a harmless re-fetch.
- **No duplicates:** hint and timer syncs are serialized and write the same thread key.
- **Bounded:** issue ids are capped at 1000 and run ids at 100 per window, with at most 20 queued hints per company. Nothing is queued while unpaired or offline.
- **Company scoping:** checked by the extension (`bridge.ts:315`), and issue and run company are verified (`sync.ts:369,708`).
- **Backoff:** hints during backoff still fetch (FR-3 negative).
- **Off by default:** consent is off by default on both sides and both must be on (`credentials.ts:20,277`; `manifest.ts:27`).
- **Read-only consent re-check:** consent is checked again before and after each read in the extension (`integration-runtime.ts:14-22`) and in the plugin (`service.ts:276-284`).
- **No stale-key fallback while linked:** a linked key is always read from Paperclip (except the F-2 path).
- **Move safety:** values are deleted only after an exact readback, in a fresh transaction, with an edit guard. A partial or interrupted move leaves no link that later gets imported (`credentials.ts:186-199,276`).
- **Rotation:** works because there is no cache and links use `version: 'latest'`.
- **Who can read a secret:** only board users holding the bridge token (`worker.ts:33`). Agent tools never reach `secret()`. Bindings are scoped to company, plugin and config path (`plugin-secrets-handler.ts:197-258`). Plugin config writes require an instance admin (`server/src/routes/plugins.ts:2394`).
- **Server log redaction:** `value`, `secret`, `authorization` and the bridge-token header are redacted (`server/src/middleware/redact-sensitive.ts:51-53,30`). Values never appear in extension error messages or logs.
- **Residual risk (not a defect):** on a `local_trusted` server, any local process counts as a board user, so the bridge token stored in the browser profile is the only barrier.

## 4. Top 3 improvements

1. Restrict secret transfer to loopback or `https`, and clear the local value when linking (F-1, F-2).
2. Stop hints from being awaited inside the bridge tick, and isolate per-issue failures (F-3, F-4).
3. Add the activity-log entry, fix the source-switch target, and fix the worker-token check (F-7, F-6, F-8).
